API danh mục PGD · v1

Hai cách xác thực: session admin đã đăng nhập (PATCH cần X-CSRFToken), hoặc Authorization: Bearer <token> cho tích hợp máy–máy (không cần cookie/CSRF). Token được tạo tại Master Data → API Token. Không có truy cập anonymous.

GET cần scope master_data:shops:read; PATCH cần master_data:shops:write. Hai quyền độc lập, chọn cả hai nếu cần đọc và ghi. Token gắn với admin tạo token; tài khoản phải đang hoạt động và còn quyền admin/Super Admin. Token GDĐB và scope intake cũ master_data:write không được tự cấp quyền cho API này. Token không thể truy cập UI quản trị hoặc tạo/thu hồi token.

MethodEndpointChức năng
GET/api/master-data/v1/shops/?q=4303&active=true&page=1Danh sách; 100 PGD/trang. q: mã/tên/email; active: true/false hoặc bỏ qua.
GET/api/master-data/v1/shops/{shop_id}/Chi tiết và orgchart.
PATCH/api/master-data/v1/shops/{shop_id}/Cập nhật một hoặc nhiều trường được phép.

Ví dụ cập nhật

shop_id là khóa chính, không phải shop_code. Các trường bỏ qua được giữ nguyên.

PATCH /api/master-data/v1/shops/123/
Content-Type: application/json
X-CSRFToken: <csrf-token>
Cookie: sessionid=<session>

{
  "shop_email": "pgd@example.com",
  "is_shop_active": false,
  "manager_id": 456
}

Email tối đa 100 ký tự; chuỗi trống để xóa email. Trạng thái phải là boolean. Tắt PGD ghi ngày đóng cửa; bật lại xóa ngày đóng cửa. manager_id phải là bộ quản lý đang hiệu lực trong danh mục Manager. Không sửa trực tiếp thông tin cá nhân quản lý trên endpoint PGD và không hỗ trợ xóa PGD.

Ví dụ dùng token

curl -X PATCH "https://<host>/api/master-data/v1/shops/123/" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"shop_email":"pgd@example.com"}'

Token chỉ hiện một lần khi tạo. Thu hồi tại UI sẽ ngừng truy cập API ngay. Khi có Authorization sai, API trả lỗi, không fallback sang session. Nhật ký thay đổi ghi token_id và người tạo token.

Kết quả

GET danh sách trả count, page, pages, results. GET chi tiết/PATCH trả shop_id, shop_code, shop_name, shop_email, is_shop_active, shop_closed_date, manager_id, orgchart.

Orgchart có manager_code, is_current, area_manager, region_manager. Mỗi quản lý có name, email, is_active. Ưu tiên AreaManager/RegionManager; nếu chưa có quan hệ, hiển thị snapshot QLKV/QLV và is_active=null. Không dùng UserProfile.region. is_current chỉ cho biết hiệu lực của bộ Manager; kiểm tra thêm is_active của từng quản lý.

Mã phản hồi

200: thành công · 400: dữ liệu sai/trường không hỗ trợ · 401: chưa đăng nhập · 403: không phải admin hoặc CSRF sai · 404: PGD không tồn tại · 405: method không hỗ trợ. Lỗi CSRF/404 có thể trả HTML mặc định Django. Thay đổi được lưu nhật ký trong Django Admin LogEntry với người thực hiện và giá trị trước/sau.
